만들게 된 계기

수익률 숫자만으로는 내 투자의 흐름을 이해하기 어려웠습니다.

기존 투자 앱은 현재 가격과 손익을 잘 보여주지만, 초보 투자자가 목표까지 얼마나 남았는지와 어떤 변화가 결과에 영향을 주었는지 이해하기는 어려웠습니다. 빠르게 확인하고 싶은 사용자와 거래 내역을 바탕으로 자세히 분석하고 싶은 사용자를 나누어, 두 가지 깊이의 분석 경험을 설계했습니다.

기술 선택

React Router 7

화면과 서버 로직을 하나의 라우트 단위로

loader와 action을 사용해 읽기와 변경의 경계를 분명히 하고, SSR과 데이터 로딩 상태를 함께 관리했습니다.

Supabase + PostgreSQL

빠른 구축과 데이터 권한 정책

Auth와 PostgreSQL을 함께 사용하고 RLS로 사용자가 자신의 데이터에만 접근하도록 데이터베이스 계층에서 제한했습니다.

Drizzle ORM

스키마와 Migration의 타입 안전성

데이터 구조와 변경 이력을 TypeScript 코드로 관리하고 애플리케이션 타입과 데이터베이스 스키마의 차이를 줄였습니다.

TypeScript

복잡한 계산 결과의 형태를 명확하게

분석 입력, 수익률 지표, AI 응답 형식을 타입으로 표현해 기능 확장 중의 실수를 줄였습니다.

문제 해결

대시보드가 4,076줄까지 커진 문제

집계와 계산을 순수 함수로 추출하고 차트, 요약 카드, 인사이트를 기능별 컴포넌트로 분리했습니다. 대시보드 진입 파일을 990줄로 줄이고 단위 테스트를 33개에서 47개로 확장했습니다.

시세 조회와 재방문의 지연

최근 10년 시세를 최초 조회 후 저장하고, 새 거래일이 확인된 경우에만 추가했습니다. 안전하게 재사용 가능한 라우트 데이터는 공통 캐시에 저장했습니다.

변경 후 오래된 분석 데이터

분석 저장과 설정 변경 시 대시보드, 기록, 인사이트, 프로필에 걸친 관련 캐시를 한 함수에서 함께 무효화하도록 통일했습니다.

외부 AI 호출 실패 가능성

핵심 투자 계산과 AI 설명을 분리했습니다. AI 요청이 실패해도 수익률과 목표 시나리오는 정상적으로 확인할 수 있습니다.

검증과 운영

기능이 동작하는 것에서 운영 가능한 구조로

  • 계산과 정책 경계값을 확인하는 단위 테스트 47개
  • 공개 페이지와 비로그인 접근 제어를 확인하는 Chromium 시나리오 11개
  • RLS, 서버 권한 확인, CSP, hCaptcha와 요청 제한 적용
  • 실제 화면 구조와 같은 스켈레톤과 캐시 무효화 원칙 문서화
